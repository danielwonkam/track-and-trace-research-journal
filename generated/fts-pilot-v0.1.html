    FTS annotation pilot — v0.1¶

    Prepared: 2026-07-28
    Status: 60 positive frames verified; no full-frame negative captured
    Purpose: validate the annotation protocol and identify missing visual conditions before freezing the first ground-truth dataset.

    Question¶

    Can a small deterministic sample from all six recordings support a consistent one-class FTS annotation workflow, and which required visual conditions remain underrepresented?

    Method¶

    The pilot sampler read the source metadata from the fixed 2026-07-27 baseline configuration. It selected eight evenly distributed interior timestamps from each recording and decoded the corresponding original-resolution frame. This produced 48 candidate images and one contact sheet per video.

    The source-video split was fixed before annotation:

    Split Videos Frames
    Train od_red_1, od_blue_1, od_white_1 24
    Validation od_red_2 8
    Test od_blue_2, od_white_2 16

    Each manifest row records dataset version, source video, timestamp, source frame index, split, image dimensions, image checksum, and the expected annotation path. The annotation and review fields begin as pending.

    No YOLO label files were created automatically. This is deliberate: a missing label means that the frame has not been annotated, while an existing empty label will mean that a human reviewer verified the frame as a negative example.

    Initial visual triage¶

    Inspection of the six contact sheets shows:

    • open-floor FTS positions in several parts of the route;
    • views in which the FTS overlaps or is partly hidden by a station;
    • station-dominated scenes relevant to the known false-lock problem; and
    • diagonal or turning poses, particularly in the later od_white_2 samples.

    This triage is not an annotation result. It does not establish the number of positive or negative frames and does not provide detector accuracy.

    AI-assisted calibration pilot — 2026-07-29¶

    Five images from different source videos and dataset splits received visual AI box proposals. The sample includes a clear station-adjacent view, station overlap and partial occlusion, an image-edge case, and two blurred diagonal poses. All proposals have medium qualitative confidence.

    The proposals are stored separately from human decisions. They do not create YOLO labels and do not increase annotation progress. In the dashboard, orange boxes mean “awaiting human verification.” A reviewer can accept, adjust, reject, or mark the image unsure. Only an explicit human save creates ground truth.

    This five-image review tests whether visual AI assistance is useful for the specific FTS appearance. The remaining 43 frames must not receive automatic proposals until the pilot boxes and class decisions have been checked.

    Human review result¶

    The reviewer completed all five AI proposals on 2026-07-29. Every proposal was saved as adjusted, rather than accepted unchanged. This result confirms that the initial visual proposals were not sufficiently localized for direct use. The corrected human boxes and proposal provenance remain stored in the append-only annotation decisions; the original images remain unchanged.

    The IoU between each original proposal and its corrected box was 0.31, 0.47, 0.46, 0.00, and 0.44 respectively (mean 0.34). One proposal missed the corrected object entirely. These five corrected boxes are ground-truth candidates for the pilot and training examples for improving a future proposal method; the small sample is not sufficient to train or validate a detector by itself.

    First-pass completion — 2026-07-29¶

    The first annotation pass is complete: 48/48 manifest frames have a saved human decision and 48 corresponding YOLO label files. An integrity audit found no missing images, decisions, labels, empty positive labels, or invalid boxes.

    All 48 frames were labelled fts_visible: 46 clear and 2 partial. The split contains 24/24 annotated train frames, 8/8 validation frames, and 16/16 test frames. The append-only history contains 50 rows for 48 latest decisions because two frames were corrected and saved more than once; only the latest decision per frame is authoritative.

    This completed the first pass, not dataset verification. The deterministic pilot contains no verified negative examples, so targeted station-only and empty-scene negatives must be added before detector evaluation claims are made.

    Validation/test quality check — 2026-07-29¶

    All 24 held-out labels received a second pass: 8 validation and 16 test. The reviewer approved all 24 saved labels without a correction or uncertainty flag. An audit found 24 unique review records, verified manifest states, and zero missing authoritative labels.

    Daniel Wonkam performed both the first pass and this second pass. This is therefore a same-reviewer quality check, not independent inter-annotator verification. The dataset must preserve that limitation in future evaluation reports. An independent reviewer would strengthen label-quality evidence if one becomes available.

    Targeted negative-candidate project — 2026-07-29¶

    The deterministic fts-negative-candidates-v0.1 project initially contained 12 pending frames: two from each recording. Its source-video split is 6 train, 2 validation, and 4 test frames. Eleven timestamps come from the latest reviewed baseline detector errors and one is an explicit recording-endpoint fallback.

    The pre-annotation artifact audit confirmed 12 readable 1920×1080 JPEGs, 12 recorded SHA-256 checksums, 12 distinct frame identifiers, and zero label or annotation-decision files. The contact sheet is consistent with the intended station-confuser and open-floor sampling, but visual triage is not a label. Every image remains a candidate, not a verified negative, until a human inspects the whole frame.

    The dashboard displays this warning and selection evidence separately from editable annotator notes. It also keeps second review disabled until all 12 first-pass decisions are saved. After that pass, the 2 validation and 4 test decisions require quality review before dataset freeze.

    Human review result¶

    The first pass and held-out quality review are complete. All 12 candidates were classified fts_visible with clear visibility; all 12 labels are non-empty. The 2 validation and 4 test decisions were approved without correction or an uncertainty flag. The append-only history contains 15 first-pass rows for 12 latest decisions and 6 review rows. A final audit found no missing decisions, reviews, labels, images, checksum mismatches, or invalid class-0 coordinates.

    This is a scientifically useful negative result for the sampling hypothesis: reviewed detector errors locate station confusers, but they do not locate full-frame FTS absence. The fixed stations still contribute background evidence inside these positive images, yet the project added zero verified empty labels. Together, the two projects now contain 60 positives and 0 full-frame negatives.

    CHRG-positive supplement — 2026-07-29¶

    The existing 66.133-second, 1920×1080, 30 FPS recording live_shopfloor_20260722_103616/camera.mp4 was inspected after the original pilot was found to lack CHRG examples. The FTS is parked at the charging station before a later manual relocation into the route. Six deterministic interior frames at 4.300, 8.567, 12.867, 17.133, 21.433, and 25.700 seconds were extracted as fts-chrg-supplement-v0.1.

    All six frames belong to the training split because the complete source contains manual hand placement and must not become held-out evaluation evidence. The selected interval precedes that relocation. Human annotation is complete: all six frames are fts_visible with clear visibility, all six labels are non-empty, and five decisions carry the station_overlap difficulty tag. The append-only history contains nine rows for six latest decisions. A final audit found no missing decisions or labels, image/checksum failures, or invalid class-0 coordinates. The verified pool therefore contains 66 positives and 0 full-frame negatives.

    Limitations found¶

    Uniform temporal sampling gives repeatable route coverage, but it does not ensure that every required condition is present. The contact sheets do not yet establish adequate coverage of:

    • verified empty scenes where no FTS pixels are visible;
    • strong motion blur;
    • difficult lighting; or
    • every degree of partial visibility.

    The six available route recordings have not yielded a frame with whole-image FTS absence. A short empty-shopfloor recording, made with the same camera and calibration while the FTS is physically outside the field of view, is now the cleanest way to add true negatives. The pilot is therefore not yet fts-ground-truth-v1 and must not be used for a final detector comparison.

    Reproduction¶

    Run the preparation script with the project interpreter:

    & .\.venv\Scripts\python.exe -m scripts.prepare_fts_annotation_pilot

    The local output is stored under data/annotations/fts-pilot-v0.1/. Raw images and labels remain excluded from Git because they derive from private shopfloor recordings. The tracked protocol and this evidence summary preserve the scientific method without publishing the media.

    Next acceptance action¶

    This action was completed on 2026-07-31. Two same-camera close-plan empty recordings produced 12 human-verified negative frames: six cluttered training examples and six clean held-out test examples. The test examples passed second review. The resulting fts-ground-truth-v1 contains 78 frames (66 positive, 12 negative), has no detected source split leakage, and has deterministic freeze SHA-256 31b68230c3dfea649ee14dae591f4a24485f68f8a787f2f13c4f4df73c95100b.

    The same person performed first annotation and held-out review, so this is a documented same-reviewer check rather than independent inter-annotator verification. The next acceptance action belongs to Milestone 3: define the fixed detector-evaluation contract before tuning or training.
