    Mistakes and lessons learned¶

    The purpose of this register is not to assign blame. A failed approach is useful when its assumptions, evidence, and correction are documented.

    L-001 — Planning documents can become inaccurate¶

    • Observed: the early backlog still described Streamlit, SQLite, YOLO, and ByteTrack while the demonstrator had moved to FastAPI, JSONL, YOLOE, and CSRT.
    • Risk: future implementation decisions could be based on an obsolete plan.
    • Correction: the FTS roadmap became the sequential source of truth, while the broad backlog was explicitly marked as containing legacy assumptions.
    • Lesson: distinguish the current implementation record from aspirational planning, and date scope changes.

    L-002 — Processing every frame can increase live latency¶

    • Observed: live preview and inference accumulated delay when older frames were retained or preview images were polled through disk files.
    • Root cause: throughput-oriented buffering conflicted with the real-time requirement for a fresh view.
    • Correction: use a dedicated capture thread, a latest-frame-only buffer, stale-frame dropping, and shared-memory preview transport.
    • Lesson: live systems should measure temporal freshness, not only average processing FPS.

    L-003 — Hard-coded camera indices are not operationally robust¶

    • Observed: an external camera could be connected but not reliably selected from a fixed index assumption.
    • Correction: enumerate available Windows cameras dynamically and expose them in the dashboard.
    • Lesson: hardware identity and availability are runtime configuration, not constants.

    L-004 — Output continuity was mistaken for evidence of tracking quality¶

    • Observed: the baseline emitted position rows for 99.8–100.0% of sampled frames, initially suggesting stable tracking.
    • Contradicting evidence: only 37 of 123 reviewed periodic detector locks were correct.
    • Root cause: CSRT can continuously track the wrong stationary object after an incorrect detector initialization.
    • Correction: add structured human review and distinguish output coverage from semantic correctness.
    • Lesson: availability of a bounding box is not evidence that the box belongs to the intended object.

    L-005 — One visual reference did not generalise across recordings¶

    • Observed: both blue recordings and od_white_1 had zero correct periodic detector locks, while the red recordings performed much better.
    • Root cause hypothesis: the single reference did not represent sufficient viewpoint, lighting, background, and appearance variation. This hypothesis requires controlled testing in Milestone 3.
    • Correction: build ground truth first, then compare multiple reference views with a dedicated one-class detector.
    • Lesson: zero-shot convenience does not remove the need for representative evaluation data.

    L-006 — Confidence was not a reliable correctness signal¶

    • Observed: mean confidence was 0.1205 for correct locks and 0.1354 for station false locks.
    • Failed proposed correction: increase the confidence threshold.
    • Reason rejected: the false locks were, on average, more confident than the correct locks.
    • Lesson: inspect class-conditional score distributions before selecting a threshold.

    L-007 — An interrupted computer invalidated a runtime measurement¶

    • Observed: od_blue_2 reported 0.51 effective FPS because wall-clock time included several hours while the computer slept.
    • Correction: label that value invalid and report CPU performance from the five uninterrupted runs, approximately 14–23 source FPS.
    • Lesson: preserve execution context and reject contaminated benchmark measurements rather than averaging them into a result.

    L-008 — Environment discovery can select the wrong virtual environment¶

    • Observed: automated environment configuration selected a neighbouring project environment, and the editor’s Python 3.15 interpreter lacked cv2.
    • Correction: run project validation explicitly with .venv/Scripts/python.exe from this project.
    • Lesson: record and verify the exact interpreter used for every experiment and validation command.

    L-009 — Repeated review saves created noisy history¶

    • Observed: 304 append-only rows represented 130 unique candidates, including 174 repeated or corrective saves.
    • Correction: preserve the valid history, summarize by latest decision, and disable saving when verdict and trimmed note are unchanged.
    • Lesson: append-only interfaces still need idempotence cues to prevent accidental duplicate user actions.

    L-010 — A review queue is not full ground truth¶

    • Observed: all detector locks and flagged anomalies were reviewed, but not every source frame with an FTS bounding box.
    • Correction: report 30.1% as checkpoint correctness, not precision, recall, or full tracking accuracy.
    • Lesson: metric names must reflect the sampling and annotation protocol that produced them.

    L-011 — A frame-level audit must not assume one visible workpiece¶

    • Observed: the first WP-1 interface replaced its only rectangle when a second piece was drawn, although several same- or different-colour pieces can coexist in one camera frame.
    • Risk: incomplete annotations would incorrectly treat unlabelled visible pieces as background and make later multi-object evaluation invalid.
    • Correction: store a frame status plus a persistent list of independently boxed instances, each with colour, visibility, context, and pixel dimensions.
    • Lesson: establish object multiplicity and annotation unit before freezing an interface or dataset schema.

    L-012 — Multi-instance frames must not share object-specific attributes¶

    • Observed: difficulty tags and notes were initially frame-level, so marking one stacked piece as occluded appeared to mark every clear piece in that frame.
    • Risk: mixed visibility conditions would be flattened into incorrect ground truth and failure analysis could not identify the affected instance.
    • Correction: store context, difficulty tags, and notes on each visible workpiece; reserve frame-level fields for absent or ambiguous decisions.
    • Lesson: decide whether every annotation field describes the frame or one object, and bind object attributes to stable instances in the interface.

    L-013 — Static cache keys must change with frontend contracts¶

    • Observed: the browser retained an older audit script after per-piece API fields changed, so the visible page and submitted payload followed different versions of the annotation contract.
    • Risk: valid-looking work could be rejected at save time without an obvious explanation to the reviewer.
    • Correction: update the JavaScript and stylesheet cache key with the contract change, and display the required reviewer identity beside Save.
    • Lesson: version static assets whenever frontend/backend contracts change; verify the script URL and submitted payload in the browser, not only unit tests.

    L-014 — Annotation propagation must remain a proposal¶

    • Observed: many workpieces remain stationary between sampled frames, making complete re-annotation repetitive.
    • Risk: automatic copy-forward can preserve disappeared or moved objects and convert reviewer expectations into false ground truth.
    • Correction: copy only on explicit request from the closest earlier reviewed same-recording frame; mark every copied box amber and block save until the reviewer confirms comparison with the current frame.
    • Lesson: annotation acceleration must preserve provenance and require fresh human verification whenever evidence changes over time.

    L-015 — Arbitrary instance limits can truncate ground truth¶

    • Observed: copying 20 reviewed boxes exhausted the original 20-instance limit, preventing annotation of a newly visible twenty-first workpiece.
    • Risk: valid visible objects would be omitted and later treated as background, corrupting detector ground truth.
    • Correction: remove the fixed per-frame instance-count limit while retaining semantic validation for every box and duplicate-box rejection.
    • Lesson: annotation capacity must follow observable scene content; defensive limits must not silently redefine the scientific annotation unit.

    L-016 — CSV generation and text writing must share one newline contract¶

    • Observed: the ignored WP-1 manifest projection contained CR CR LF separators and blank rows after dashboard saves on Windows.
    • Root cause: csv.DictWriter emitted CR LF, then Path.write_text translated the embedded line feed again while atomically replacing the file.
    • Risk: parsers tolerated the blank rows, but the projection failed Git's whitespace check and was not byte-clean reproducible evidence.
    • Correction: write the generated CSV content through a text handle opened with newline="" and assert that saved manifests never contain CR CR LF.
    • Lesson: generate and persist CSV under one explicit newline policy; test raw bytes on the operating system that writes the artifact.

    L-017 — A dual-load clip does not imply dual-load context in every frame¶

    • Observed: the replacement sequence has 30 frames with two on_fts labels; the blue object's remaining contexts include handover, station and elsewhere.
    • Risk: earlier blanket visual claims or scenario names could cause valid transfers to be overwritten merely to satisfy an expected object count.
    • Correction: prepare image-based same-reviewer QA of the full replacement sequence, preserve original labels, and require a reason for each correction.
    • Lesson: distinguish clip-level scenario coverage from frame-level context; structural checks and consistent counts cannot substitute for visual evidence.

    L-018 — A blocked evidence gate must disable the annotation workflow¶

    • Observed: an HTTP 409 left the QA view blank while edit, zoom and save controls still appeared usable. A same-label re-save, not lost annotations, caused the history checksum mismatch.
    • Correction: use explicit loading, ready, empty and blocked states; clear stale images, guard pointer/keyboard/save actions and explain recovery. Label interaction mode and zoom as separate groups.
    • Lesson: test failed metadata and image loads as well as successful startup. Human-label preservation and a usable error state are both necessary; a backend rejection alone is not an adequate interface.

    L-019 — Validate rendered themes and the delivered archive, not settings alone¶

    • Observed: a custom dark scheme left near-black text on a dark navy background. Directory-style URLs and an untested search worker also made prior claims about direct-file portability insufficiently supported.
    • Correction: use full native colour schemes and measure computed text and background colours. Build explicit HTML links and bundled offline search; verify an extracted archive in a standard browser with networking disabled. On Windows, a pinned JavaScript URL with a real extension avoids the asset downloader's unsupported symbolic-link path.
    • Lesson: configuration labels do not establish readable output, and a successful server preview does not establish portable offline behaviour. Keep translated summaries distinct from original technical evidence.
