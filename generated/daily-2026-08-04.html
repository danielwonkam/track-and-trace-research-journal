    Daily research journal — 2026-08-04¶

    Objective¶

    Complete the one-time locked temporal test of YOLO11n + CSRT versus YOLO11n + ByteTrack without changing the frozen detector, tracker configurations, or validation-selected winner.

    Supervisor meeting¶

    The supervisor requested that the complete OSF shopfloor factory map be brought into the project and suggested extending the system to identify and track the workpieces. The map integration was taken as the immediate task; workpiece tracking remains a proposed next stage requiring separate validation.

    Work completed¶

    • Completed all 472 first-pass temporal annotations: 236 train, 72 validation, and 164 test.
    • Completed second review of all validation and test rows.
    • Built hash-bound, resumable validation and test YOLO detection caches and reused each cache for both trackers.
    • Added deterministic tracker-output resume through cached-frame replay.
    • Evaluated both candidates on validation, applied the predeclared selection rule, and created immutable locks before test evaluation.
    • Selected locked_yolo11n_plus_csrt from validation F1 and coverage.
    • Completed both locked full-video test runs and generated final metrics.
    • Added a read-only browser progress monitor that observes evidence files but cannot start, stop, or modify experiments.
    • Started the final frozen YOLO11n + CSRT coverage run for the remaining train-role recordings: od_red_1, od_blue_1, od_white_1, and the cluttered empty close-plan control. This completes all six route recordings when combined with the already finished validation and locked-test outputs. The 30,627-frame workflow uses the resumable detector cache and will compute train metrics after the full CSRT output is complete.
    • Paused that additional coverage run after clarifying its purpose. It is not required to select the tracker or validate the locked conclusion, which is already complete. The partial detector cache remains resumable if complete six-route descriptive coverage is later required for the thesis.
    • Resumed the retained train-role cache after an explicit request to provide frozen YOLO11n + CSRT results for all six original route videos in the dashboard. This is descriptive deployment evidence only; it does not reopen model selection or change any frozen setting.
    • Added an atomic replay publisher that projects immutable combined prediction evidence into per-session fts_locked.jsonl files without replacing older workpiece or FTS evidence. The dashboard now prefers this selected-pipeline projection, discovers FTS-only replay sessions, and displays tracker state and detector-plus-tracker FPS.
    • Published and verified the three already complete route replays: od_red_2 (9,565 frames), od_blue_2 (10,846), and od_white_2 (10,432). API verification at 60 seconds returned an annotated JPEG, a detected FTS, and pipeline telemetry; browser verification showed the recorded frame, digital-twin FTS marker, tracker state, and FPS.
    • Completed the 30,627-frame train-role CSRT run and published the remaining od_red_1 (9,351 frames), od_blue_1 (10,762), and od_white_1 (9,517) trajectories. Session replay now exposes exactly the six requested original route videos.
    • Replaced repeated replay-frame requests with continuous native MP4 playback, one compact trajectory download, and frame-synchronized browser overlays. Removed repeated video seeking and verified continuous 1x playback.
    • Restored FTS-only Event Stream and Traceability behavior without rerunning inference. Station visits require both calibrated docking-area occupancy and a continuous low-motion interval; brief in-station manoeuvres remain one visit. Replay now shows ARRIVED/DEPARTED events, station order, active visits, and completed dwell durations.
    • Deferred physical live-camera validation because the operator is away from the test station. A brief local-camera launch was stopped, created no logs or video recording, and is not treated as station evidence.
    • Aligned Live tracking with the selected Session replay behavior. The live subprocess now runs only the hash-verified supervised YOLO11n detector and selected CSRT tracker, publishes only the FTS, draws its compact dotted camera-space path, and derives Event Stream and Traceability visits from the same calibrated service-area plus low-motion criteria used by replay. Legacy workpiece detections and custody events are no longer exposed by Live mode. The interface and automated contracts were validated off-station; the structured physical route remains pending.

    Results¶

    Validation contained 72 positive truth points and no negative controls. CSRT recorded 72 TP, 0 FP, and 0 FN: precision, recall, F1, and temporal coverage were 1.000; mean IoU was 0.816; mean pipeline time was 332.1 ms (3.01 FPS). ByteTrack recorded 46 TP, 0 FP, and 26 FN: precision 1.000, recall/coverage 0.639, F1 0.780, mean IoU 0.804, and mean pipeline time 79.4 ms (12.59 FPS). CSRT therefore won under the declared validation-first rule.

    The locked test contained 164 truth points: 144 positive and 20 negative.

    Candidate TP FP FN Precision Recall F1 Coverage Mean IoU Mean ms FPS
    YOLO11n + CSRT 144 0 0 1.000 1.000 1.000 1.000 0.821 220.7 4.53
    YOLO11n + ByteTrack 88 0 56 1.000 0.611 0.759 0.611 0.820 62.6 15.98

    CSRT had no false lock, missed interval, reacquisition, fragment, or ID switch. ByteTrack had a 7.5-second longest miss, three reacquisition events, two unrecovered losses, three fragments, and three ID switches. Both trackers produced zero false positives on all 20 sampled empty-source frames.

    Interpretation¶

    The frozen conclusion is YOLO11n + CSRT for the present one-object FTS task. ByteTrack is approximately 3.5 times faster on test, but its repeated losses make it unsuitable under the declared accuracy-first selection rule. No post-test threshold or tracker tuning is permitted for this experiment.

    Limitations¶

    • Temporal truth is sampled at approximately 2 Hz, so interval measurements are quantized to 0.5 seconds.
    • Validation has no negative frames; empty-scene rejection is supported only by the 20 test controls.
    • Test second review was completed before tracker locks. The evaluation runner nevertheless did not read test truth until lock validation succeeded.
    • First and second reviews were performed by the same person.
    • The result covers selected windows from two positive test videos and one clean empty video under fixed close-plan camera geometry; it is not proof of arbitrary-camera or low-light generalization.

    Next step¶

    Perform the structured physical live-camera route later at the test station; do not treat the laptop-camera check as operational evidence.
