    FTS Detection and Camera Calibration Roadmap¶

    This is the active, sequential roadmap for the current computer-vision work. It is intentionally separate from TODO.md, which remains the broad thesis planner and contains outdated implementation assumptions.

    Working rule: only one milestone may be marked IN PROGRESS. Complete its acceptance gate before starting the next milestone. Findings, commands, metrics, and output paths must be recorded under the milestone before it is closed.

    Status legend: ⬜ NOT STARTED · 🔄 IN PROGRESS · ✅ DONE · ⛔ BLOCKED

    Goal¶

    Reliably detect and track the fischertechnik FTS vehicle in recorded and live shopfloor video, then provide repeatable camera/station calibration so station polygons remain correct whenever the camera is moved or reinstalled.

    Following the supervisor meeting on 2026-07-28, this roadmap is also the active scope boundary: finish the FTS before extending workpiece tracking, custody assignment, complete event reconstruction, or detailed dashboard statistics. The scientific work record is maintained under docs/research/.

    Ground truth about the current implementation¶

    • The selected FTS pipeline uses the frozen one-class supervised YOLO11n checkpoint with immutable confidence and inference settings.
    • OpenCV CSRT is the validation-selected tracker and is corrected from frozen YOLO11n detections on every processed source frame.
    • Candidate selection uses physical and temporal constraints.
    • Station and service-area polygons are currently fixed pixel coordinates in configs/cameras/cam1_zones.yaml for a 1920×1080 view.
    • Six recorded test sessions are available: two red, two blue, and two white.
    • Work must be validated offline before changes are transferred to live tracking.

    ✅ Milestone 1 — Establish the FTS baseline on all six videos¶

    Purpose: determine exactly how and where the current YOLOE + CSRT pipeline fails. Do not tune the detector before this evidence exists.

    • Inventory the six MP4 recordings and record resolution, FPS, duration, and frame count.
    • Run the same current FTS configuration on all six videos.
    • Save per-video FTS tracks, detector locks, confidence, and annotated debug video/frames.
    • Classify failures: missed FTS, false FTS, station selected as FTS, CSRT drift, lost track, and incorrect reacquisition.
    • Record runtime and effective FPS on the current CPU machine (excluding the sleep-interrupted od_blue_2 runtime).
    • Save a baseline summary in experiments/runs/20260727_fts_baseline/.

    Current result (2026-07-27): automated processing is complete for all six videos. Output continuity is 99.8–100.0%, with four suspicious jumps and low mean detector confidence (0.114–0.136). Output continuity was not treated as an accuracy result; the manual review below tested whether the checkpoints actually showed the FTS. See experiments/runs/20260727_fts_baseline/SUMMARY.md.

    Review workflow available: open the FastAPI dashboard and select FTS review. The queue includes each YOLOE detector lock, suspicious jump, and no-output gap. Inspect the annotated frame, scrub ±1 second when needed, then save one structured verdict. Decisions are append-only in experiments/runs/20260727_fts_baseline/failure_review.jsonl; saving a newer decision corrects the displayed verdict without deleting its history.

    Final reviewed result (2026-07-28): all 130 queued candidates were reviewed. Only 37 of 123 periodic YOLOE locks (30.1%) were correct. The latest candidate verdicts contain 82 station false locks, 8 wrong objects, 2 tracker-drift observations, and 38 correct FTS observations. Both blue videos and od_white_1 had zero correct periodic detector locks. See experiments/runs/20260727_fts_baseline/REVIEW_SUMMARY.md and review_summary.json.

    The milestone is closed as a reproducible candidate-level baseline. Precision, recall, and exhaustive track-drift duration remain intentionally unreported because they require frame-level ground truth from Milestone 2.

    Acceptance gate

    • All six videos have reproducible outputs from one recorded configuration.
    • Every queued detector lock, suspicious jump, and no-output gap has a timestamp and failure category.
    • Output coverage, candidate false-lock count, longest no-output gap, and valid CPU FPS are reported.
    • Candidate-level interpretation limits and the need for frame-level ground truth are documented.

    ✅ Milestone 2 — Build a small verified FTS ground-truth dataset¶

    Purpose: create trustworthy evidence for evaluation and possible supervised training. The workpiece colour is incidental; the annotation class is fts.

    • Sample frames from all six videos, including motion blur, stations, turns, and occlusion.
    • Annotate the FTS bounding box as one class: fts.
    • Include negative frames where no FTS is visible.
    • Split by source video, not random neighbouring frames, to prevent leakage.
    • Create train/validation/test manifests with source video and timestamp.
    • Manually review every validation and test annotation.

    Pilot started — 2026-07-28: The annotation protocol and deterministic fts-pilot-v0.1 sampler were created. Forty-eight pending frames (eight per video) were extracted with source-video splits, timestamps, frame indices, checksums, and contact sheets. Manual boxes and validation/test review are still required. Initial contact-sheet triage found open-floor, station-overlap, and turning views; targeted sampling is still needed if empty scenes, strong motion blur, or difficult lighting remain absent after classification.

    First pass complete — 2026-07-29: All 48 frames now have human decisions and YOLO labels. An integrity audit found zero missing or inconsistent artifacts. The pilot contains 48 positives (46 clear, 2 partial) and no negatives. Milestone 2 therefore remains active: all 24 validation/test labels require second review, and targeted station-only and empty-scene negatives must be sampled and annotated before the acceptance gate can pass.

    Same-reviewer check complete — 2026-07-29: All 8 validation and 16 test labels were approved on a second pass with zero corrections or uncertainty flags. The first annotator and reviewer were both Daniel Wonkam; this is a documented quality check, not independent inter-annotator verification. The remaining acceptance blocker is targeted negative sampling and review.

    Targeted-negative candidates ready — 2026-07-29: A separate deterministic fts-negative-candidates-v0.1 project initially contained 12 pending frames (two from each recording) while preserving the source-video split. Candidate timestamps prefer latest reviewed detector-error evidence, but are not automatically classified: no labels were created during extraction. Human whole-frame decisions were therefore required. The dashboard identifies them as candidates and does not enable second review until all 12 first-pass decisions are complete.

    Targeted-negative result — 2026-07-29: The first pass and held-out review are complete. All 12 candidates were clear positives with non-empty labels; all 2 validation and 4 test decisions were approved. The artifact audit found zero structural issues. Reviewed detector-error timestamps therefore improved station-confuser background coverage but failed to provide whole-frame absence. The verified pool now has 60 positives and 0 negatives. Milestone 2 remains active pending a same-camera empty-shopfloor recording and verified empty labels; further mining of the same route recordings is not assumed to solve it.

    CHRG coverage supplement complete — 2026-07-29: The existing same-camera recording live_shopfloor_20260722_103616/camera.mp4 contains the FTS parked at CHRG before it is manually relocated into the route. Six deterministic frames from 4.300–25.700 s form fts-chrg-supplement-v0.1. The complete source is train-only because manual placement is an acquisition artifact that must not enter validation or test evaluation. Human annotation is complete: all six are clear fts_visible frames with valid non-empty labels; five carry the station_overlap difficulty tag. The artifact audit found no missing decisions, labels, image/checksum failures, or invalid class-0 coordinates. The verified pool now has 66 positives and 0 full-frame negatives.

    Declared-empty sources ready — 2026-07-31: Eight new 1920×1080 recordings were inventoried and visually triaged. Two close-plan empty recordings match the operational camera framing. Six deterministic cluttered frames are assigned to training and six clean frames to held-out test in fts-verified-negatives-v0.1. Extraction created no labels or decisions; all 12 require whole-frame human verification, and the 6 test decisions require a second pass. The wide-plan empty source is reserved for out-of-distribution stress testing because its camera geometry differs. Four low-light route videos and one cluttered CHRG-positive video are preserved for later robustness work.

    Verified negatives and freeze complete — 2026-07-31: All 12 close-plan candidates were manually classified as no_fts; the six held-out test frames also passed the required second review. Each retained negative has an existing empty YOLO label. The fail-closed freezer combined the four completed source projects into fts-ground-truth-v1: 78 frames comprising 66 positives and 12 negatives (train 42, validation 10, test 26). All images match their recorded checksums, all labels are valid, all 36 held-out rows are second-reviewed, and no duplicate frame, duplicate image, or source-video split leakage was found. The deterministic freeze SHA-256 is 31b68230c3dfea649ee14dae591f4a24485f68f8a787f2f13c4f4df73c95100b. All held-out checks were performed by the first annotator, Daniel Wonkam; this is a documented same-reviewer quality check, not independent inter-annotator verification.

    Acceptance gate

    • All six route videos contribute verified positive and difficult examples; two additional split-disjoint close-plan sources contribute 12 verified whole-frame negatives.
    • Validation and test frames do not come from the same source videos as training frames.
    • Annotation quality is manually verified and fts-ground-truth-v1 is recorded with immutable source evidence and a deterministic freeze hash. The same-reviewer limitation remains explicit.

    ✅ Milestone 3 — Improve and compare FTS detectors offline¶

    Purpose: select the simplest detector that is demonstrably reliable on unseen recorded video.

    • Select the current YOLOE reference image and box using training/validation data only; retain the existing confidence and candidate constraints for the detector comparison.
    • Test four predeclared diverse FTS reference views rather than relying on one favourable appearance.
    • Train a lightweight YOLO11n one-class fts detector as the supervised alternative.
    • Compare YOLOE and the dedicated detector on identical held-out frames from source-isolated videos.
    • Report precision, recall, F1, false positives, false negatives, AP50, IoU, and CPU inference time.
    • Select the winner from measured accuracy and edge performance, not visual impression.

    Evaluation contract and unchanged validation baseline — 2026-07-31: The fixed contract uses IoU 0.50, validation-only configuration selection, complete per-frame prediction evidence, warmed CPU timing, and a machine-enforced sealed test gate. On the 10 positive validation frames, the unchanged constrained single-reference YOLOE method produced 3 TP, 5 FP, and 7 FN: precision 0.375, recall 0.300, F1 0.333, AP50 0.178, and 165.2 ms mean detector inference (6.05 effective FPS). The 26 test frames remain unopened.

    Validation selection complete — 2026-07-31: The predeclared center-transit training prompt produced 10 TP, 0 FP, and 0 FN on validation (P/R/F1/AP50 all 1.000, mean IoU 0.798, 178.0 ms). YOLO11n early-stopped after 40 epochs and selected epoch 20; training evaluation recorded precision 0.99365, recall 1.000, mAP50 0.995, and mAP50–95 0.8685. At the selected fixed-contract confidence 0.05, YOLO11n also produced 10 TP, 0 FP, and 0 FN (P/R/F1/AP50 all 1.000), with mean IoU 0.916 and 50.4 ms inference (19.85 FPS). Validation has no negatives, so neither precision result establishes empty-scene rejection. The 26 test frames remain unopened pending immutable candidate locks.

    Locked final result — 2026-07-31: Both candidates were locked before the single 26-frame test release. YOLOE produced TP 15, FP 11, and FN 5: precision 0.577, recall 0.750, F1 0.652, AP50 0.594, mean IoU 0.779, and 179.4 ms CPU inference (5.57 FPS); it rejected 0/6 empty frames. YOLO11n produced TP 20, FP 0, and FN 0: precision, recall, F1, and AP50 all 1.000, mean IoU 0.890, and 59.6 ms (16.77 FPS); it rejected 6/6 empty frames. The selected detector is supervised-yolo11n-v1. No post-test tuning was performed.

    Acceptance gate

    • Both approaches are evaluated on identical held-out data.
    • The selected detector achieved perfect metrics on the fixed test sample and approximately 16.77 FPS on the recorded CPU environment.
    • The selection decision and still-frame/sample-size limitations are written down.

    🔄 Milestone 4 — Make recorded-video FTS tracking robust¶

    Purpose: produce a continuous, physically plausible FTS trajectory after the detector itself is reliable.

    • Compare CSRT with a detector-driven tracker such as ByteTrack or BoT-SORT.
    • Add track confidence/state: detected, predicted, lost, and reacquired.
    • Reject impossible jumps using elapsed time, guide paths, and calibrated operational bounds.
    • Prevent static stations from becoming a persistent FTS track.
    • Measure ID switches, track coverage, drift duration, and reacquisition delay.
    • Run the final offline tracker on all six videos.

    Temporal evaluation protocol prepared — 2026-07-31: fts-tracking-evaluation-v1 binds the immutable supervised-yolo11n-v1 detector and forbids detector checkpoint or threshold tuning. Complete sources remain isolated: three route sources plus the cluttered empty source are train, od_red_2 is validation, and two route sources plus the clean empty source are sealed test. Candidate tracker families are YOLO11n + CSRT and YOLO11n + ByteTrack; configuration and selection may use train/validation only.

    Content-blind sequence extraction complete — 2026-07-31: Three predeclared 12-second windows per route source were sampled at 2 Hz, and each empty source contributes 20 duration-scheduled frames. The resulting fts-tracking-sequences-v0.1 project has 472 pending candidates: 236 train, 72 validation, and 164 test. Audit found 472 images and provenance rows, zero labels, zero annotation decisions, zero duplicate frame IDs, and zero duplicate image hashes. Human annotation is now required; the tracking-test labels remain sealed until tracker candidates are locked. The protocol SHA-256 is 6059de13fe1821f700a15c7d1c00e7bea6cd4a9ca3008aace21b9e45b3d0ddb7.

    Tracker implementation gate complete — 2026-07-31: The exact selected detector is now enforced by checkpoint SHA-256 and immutable inference settings. Full-video runners for CSRT and the installed Ultralytics 8.4.96 ByteTrack API process every decoded source frame, write explicit empty/lost rows, and record track ID, state, confidence, box, and pipeline timing. The evaluator rejects non-sequential or incomplete source coverage, source-role drift, declaration drift, detector-hash drift, and tracking-test access without a matching candidate lock. Implemented metrics are tracking precision/recall/F1, temporal coverage, matched IoU, false-positive duration, longest false lock, longest miss, reacquisition delay, fragments, ID switches, full-video mean/p95 latency, and effective FPS. Eleven focused tests and all 91 project tests pass. This is an implementation result only; temporal labels and measured candidate results are still pending.

    Locked tracker comparison complete — 2026-08-04: Human temporal evidence is complete for all 472 sampled frames, including second review of all 72 validation and 164 test rows. Validation selected YOLO11n + CSRT before test release: CSRT achieved F1 and temporal coverage 1.000 versus ByteTrack F1 0.780 and coverage 0.639. Immutable candidate locks were created on 2026-08-03.

    The one-time locked test contained 164 truth points: 144 positive points across od_blue_2 and od_white_2, plus 20 negative points from the clean empty source. CSRT produced 144 TP, 0 FP, and 0 FN (precision, recall, F1, and coverage 1.000), mean matched IoU 0.821, no missed interval, no fragments, no ID switches, and 220.7 ms mean pipeline time (4.53 FPS). ByteTrack produced 88 TP, 0 FP, and 56 FN (precision 1.000, recall/coverage 0.611, F1 0.759), mean matched IoU 0.820, a 7.5-second longest miss, three reacquisitions, two unrecovered losses, three fragments, three ID switches, and 62.6 ms mean time (15.98 FPS). Both rejected every sampled clean-empty frame. The frozen winner remains locked_yolo11n_plus_csrt; no test-driven tuning was performed.

    The comparison experiment is complete, but Milestone 4 remains open. The selected pipeline must still be run as the final configuration over all six route recordings, and the predeclared jump/guide-path operational safeguards must be implemented and evaluated. Validation contained no negative frames, test truth was second-reviewed before candidate locks (although the evaluator did not read it before locking), and 2 Hz truth quantizes interval metrics to 0.5 seconds.

    Final six-route coverage started — 2026-08-04: The frozen winner is now processing the three remaining train-role route recordings plus their cluttered empty control (30,627 total frames). The validation and test outputs already cover the other three route recordings. Detector caching, CSRT output, and the subsequent train-role metrics are resumable and visible in the read-only experiment monitor. No checkpoint, confidence threshold, or tracker setting was changed.

    Optional coverage paused — 2026-08-04: This extra descriptive run was stopped after scope clarification because tracker selection and its locked test are already complete. It does not train or improve the model. Its partial cache is retained for deterministic resume if complete six-route evidence is later required; it is not a blocker for operational-safeguard development.

    Six-video dashboard replay explicitly resumed — 2026-08-04: The user requested selected-pipeline playback for the six original route recordings while physical test-station access is unavailable. The three completed validation/test route outputs are published in dashboard Session replay; their recorded frames, FTS boxes, digital-twin positions, tracker states, and pipeline FPS were verified through the API and browser. The retained train-role cache is being resumed for od_red_1, od_blue_1, and od_white_1; the protocol-associated cluttered empty control is processed in the same immutable stream. This work does not tune or relock the detector or tracker.

    Acceptance gate

    • The selected tracker outperforms the current baseline on the six recordings.
    • No known station false lock persists as the FTS.
    • Tracking metrics and representative debug outputs are saved reproducibly.

    ⬜ Milestone 5 — Add repeatable camera and station recalibration¶

    Purpose: prevent oversized, overlapping, or displaced station polygons when the camera position, zoom, resolution, or crop changes.

    • Add a calibration mode that displays a frozen camera frame at the actual processing resolution.
    • Let the operator draw/edit each station polygon and the tighter FTS service/docking area separately.
    • Show polygon overlap, out-of-frame points, and minimum-gap warnings before saving.
    • Store calibration with camera name, resolution, timestamp, and optional reference-frame checksum.
    • Refuse or clearly warn when a calibration resolution does not match the incoming video.
    • Provide preview and confirmation before replacing an existing calibration.
    • Document the physical procedure: camera mounting, framing, station outlining, validation drive, and rollback.

    Acceptance gate

    • A user can recalibrate without editing YAML manually.
    • Invalid or overlapping station geometry is visibly flagged.
    • Saved polygons align with the camera frame and survive an application restart.
    • A known FTS pass through every reachable station validates the docking areas.

    🔄 Milestone 6 — Transfer the verified pipeline to live tracking¶

    Purpose: integrate only the detector, tracker, and calibration proven by the offline milestones.

    • Integrate the selected FTS detector and tracker into the latest-frame live pipeline.
    • Load calibration by the selected camera and verify resolution compatibility at startup.
    • Keep capture/preview independent from inference so stale frames are discarded.
    • Display detector/tracker state, confidence, FPS, and calibration warnings in the dashboard.
    • Run a structured shopfloor validation route covering all stations and difficult transitions.
    • Compare live results with the six-video offline benchmark and document remaining domain shift.

    Implementation and offline fallback ready — 2026-08-04: The live process now verifies and loads the frozen YOLO11n checkpoint, runs the selected CSRT tracker, preserves the existing xywh/event contracts, and publishes current state and FPS through the latest-frame preview. Recording remains opt-in. The dashboard also provides selected-pipeline replay for the original videos. A structured physical camera route remains deferred until the operator returns to the test station; no off-site camera check is accepted as live evidence.

    Acceptance gate

    • Live tracking completes the agreed station route without persistent false locks.
    • Visual latency, FTS coverage, false locks, and station arrival accuracy meet recorded targets.
    • A fallback recorded demonstration and rollback configuration are available.

    Required evidence for every milestone¶

    • Exact command or configuration used.
    • Input video/session identifiers.
    • Code revision or commit identifier.
    • Machine and model/runtime information.
    • Quantitative metrics, not only screenshots.
    • Debug outputs for failures as well as successes.
    • Short conclusion stating whether the acceptance gate passed.

    Scope control¶

    Milestones 1 and 2 have passed. Continue with offline detector comparison in Milestone 3 using the fixed fts-ground-truth-v1 split. Do not use test labels to tune prompts, thresholds, constraints, hyperparameters, or checkpoints. Station calibration requirements may be documented earlier, but implementation starts at Milestone 5 unless an offline experiment is blocked by invalid geometry.
