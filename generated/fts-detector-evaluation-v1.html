    FTS detector evaluation contract v1¶

    Status: active development contract; test split sealed
    Dataset: fts-ground-truth-v1
    Freeze SHA-256: 31b68230c3dfea649ee14dae591f4a24485f68f8a787f2f13c4f4df73c95100b
    Runtime target: CPU

    Purpose¶

    This contract prevents detector selection from adapting to the held-out test images. It applies to the YOLOE visual-prompt candidate and the lightweight one-class supervised candidate. Both methods must use the same frozen images, matching rule, metrics, and runtime measurement procedure.

    Evidence partitions¶

    Phase Permitted evidence Prohibited use
    Development 42 train frames Final accuracy claim
    Selection 10 validation frames Reading test labels or selecting from test results
    Final comparison 26 test frames Any further threshold, prompt, constraint, hyperparameter, or checkpoint change

    The complete source recording remains assigned to one partition. Frames must not be copied across partitions. Before every run, the dataset freeze hash must match the value above.

    Candidate A — YOLOE visual prompting¶

    Development may compare a small declared set of FTS reference views from training sources. Reference image, reference box, model checkpoint, image size, confidence threshold, and candidate constraints are selected only from training and validation evidence. The final configuration is written to an immutable run record before test inference.

    Candidate B — one-class supervised detector¶

    Training uses only the 42 training images. Epoch count, augmentation, architecture, image size, and confidence threshold are selected using the 10 validation images. The exact checkpoint SHA-256 and inference configuration are recorded before test inference. Test images are not used for early stopping or checkpoint selection.

    The initial candidate should be a lightweight Ultralytics detection model that can run on the target CPU. Architecture choice must be confirmed from installed Ultralytics support and measured locally rather than inferred from published GPU benchmarks.

    Matching and metrics¶

    The task has one class, fts, and at most one verified FTS per frame. A prediction is a true positive when its xyxy box has intersection-over-union of at least 0.50 with the ground-truth box. A ground-truth box can match only one prediction. Additional predictions are false positives. An unmatched positive is a false negative; any prediction on a verified negative is a false positive.

    Primary metrics:

    • precision;
    • recall; and
    • F1.

    Secondary evidence:

    • AP50;
    • mean IoU among true positives;
    • number of false-positive frames and false negatives;
    • per-frame detection records;
    • mean and 95th-percentile inference latency; and
    • effective inference FPS.

    Metrics are computed by tracktrace.evaluate. Confidence thresholds are chosen on validation data and then held fixed. Results must include raw integer counts, not only ratios.

    CPU timing procedure¶

    Load the model before timing, process three untimed warm-up images, then time each image with the same image size and device setting. Report mean and 95th-percentile latency and effective FPS. Model loading, file decoding, and visualization are excluded from inference latency and may be reported separately. The machine, Python, PyTorch, Ultralytics, and OpenCV versions must be captured in the run record.

    Test release gate¶

    The test split may be opened exactly once for the primary comparison after:

    1. the YOLOE reference set and all inference constraints are locked;
    2. the supervised checkpoint and confidence threshold are locked;
    3. validation predictions and metrics are stored for both candidates; and
    4. both run records identify this contract and the frozen dataset hash.

    After test release, poor results are findings—not permission to retune and report on the same test set. Any later method change requires a new held-out dataset version or must be labelled exploratory.

    Known limitations¶

    • The dataset has only 78 frames and 12 negatives.
    • The 12 negatives come from two deliberately empty close-plan recordings.
    • The first annotator also performed all held-out second reviews; this is not independent inter-annotator verification.
    • The wide-plan source is excluded from the core comparison and reserved for a separately labelled camera-geometry stress test.

    Validation selection record — 2026-07-31¶

    Four YOLOE prompts were declared from od_red_1 training boxes before validation inference. The selected center-transit prompt produced 10 TP, 0 FP, and 0 FN on the 10 positive validation frames: precision, recall, F1, and AP50 were all 1.000, mean matched IoU was 0.798, and mean CPU inference was 178.0 ms.

    The first supervised candidate used YOLO11n, seed 31, image size 640, and the declared train-only development view. Early stopping completed 40 of 100 planned epochs and selected epoch 20. Ultralytics' best-epoch validation metrics were precision 0.99365, recall 1.000, mAP50 0.995, and mAP50–95 0.8685. Under this contract's frame evaluator, confidence 0.05 produced 10 TP, 0 FP, and 0 FN: precision, recall, F1, and AP50 were all 1.000; mean matched IoU was 0.916; mean/p95 CPU inference was 50.4/53.1 ms (19.85 FPS).

    These validation results establish positive-frame localisation only. The validation split has no verified negative frames, so its precision value cannot establish empty-scene rejection. That question remains sealed in the final test comparison.

    Locked final comparison — 2026-07-31¶

    Both candidates were locked before test access, including artifact hashes, runtime parameters, validation metrics, and software versions. The 26-frame test was then released exactly once; it contains 20 positive and six verified empty frames.

    Candidate TP FP FN Precision Recall F1 AP50 Mean IoU Mean CPU FPS
    YOLOE prompt 15 11 5 0.577 0.750 0.652 0.594 0.779 179.4 ms 5.57
    YOLO11n 20 0 0 1.000 1.000 1.000 1.000 0.890 59.6 ms 16.77

    YOLOE rejected none of the six empty frames; supervised YOLO11n rejected all six. supervised-yolo11n-v1 is therefore selected under the predeclared F1-first rule and is approximately 3.0 times faster by mean CPU inference. No post-test tuning was performed. This conclusion is limited to still-frame detection; tracking, low-light, camera-geometry shift, and production behavior remain separate experiments.
